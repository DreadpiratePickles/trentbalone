## 3. What Hermes explicitly lacks

- **No supported PyPI, brew or AUR install, and no Intel macOS support** — these distribution methods are listed as unsupported and PRs to fix them will not be accepted. (/docs/getting-started/platform-support)
- **Dashboard embedded terminal does not run on native Windows** — needs a POSIX PTY; ConPTY is called out as future work. (/docs/user-guide/windows-native)
- **Termux lacks the Docker backend, local `faster-whisper` transcription and browser automation.** (/docs/getting-started/termux)
- **Kanban is deliberately single-host** — a shared board across two machines is not supported because crash detection assumes host-local PIDs. (/docs/user-guide/features/kanban)
- **Multiplexing isolates profiles, not end users** — request-level identity and per-user authorization above the profile layer are an explicit non-goal, and MCP discovery, terminal env and the built-in tool registry are still process-global. (/docs/developer-guide/multiplexing-gateway)
- **Managed scope v1 is a convenience boundary, not an unescapable sandbox** — no hard boundary, no macOS/Windows native managed locations, no `managed.d/` fragments, no signed managed files, no MDM delivery. (/docs/user-guide/managed-scope)
- **Egress credential brokering does not cover signature-auth providers** — AWS SigV4 keys and Google application credentials stay real inside the sandbox and only produce warnings. (/docs/user-guide/egress/iron-proxy)
- **Codex app-server runtime disables `delegate_task`, `memory`, `session_search` and `todo`**, and cannot guarantee sub-second cancellation. (/docs/user-guide/features/codex-app-server-runtime)
- **Video edit and extend are out of scope for the generic `video_generate` backend contract** (only xAI-specific tools exist). (/docs/developer-guide/video-gen-provider-plugin)
- **Token and cost analytics are an explicit local lower-bound estimate**, excluding auxiliary calls, retries, fallbacks and cache writes; off by default. (/docs/user-guide/configuration)
- **Trajectory export and Atropos RL have no `hermes` CLI or config surface** — export is a `run_agent.py --save_trajectories` / library switch, and Atropos is an external repo. (/docs/developer-guide/trajectory-format)
- **Landed then reverted, not shipping in v0.21.0**: Model Council mode (`/council`), the DCP context engine, and the WS-only gateway server. (release v2026.8.31 notes)
- **Open feature requests confirm absent capabilities**: no native mobile app (#11911), no gateway role-based access control tiers (#527), no cloud sync of configuration across devices (#20510), no pluggable SessionDB backend such as PostgreSQL (#23717), no desktop system-tray background mode (#38007), no remote-agent-with-local-tool-execution split (#18715), no cross-platform session handoff beyond `/handoff` (#8366), no Mistral first-party provider (#20859), no SearxNG web-search backend (#5941), no configurable temperature (#17565). Marked **inferred** as absence: an open issue is primary evidence that the work is requested, not proof the feature is missing from an unreleased branch.
- **No `CHANGELOG.md`** in the repository; release notes exist only on the GitHub releases page.

## 4. Hermes design principles worth copying

1. **Prompt stability as a hard rule.** The system prompt does not change mid-conversation; no cache-breaking mutation except an explicit user action such as `/model`. Memory writes land on disk but do not re-enter the prompt until the next session. (/docs/developer-guide/architecture, /docs/user-guide/features/memory)
2. **Three-tier prompt assembly ordered for longest-prefix cache reuse.** stable then context then volatile, with shared project context placed before any cwd-dependent line so sessions in different worktrees share a cacheable prefix. (/docs/developer-guide/prompt-assembly)
3. **Bounded memory that refuses to silently forget.** A write past the character limit returns an error carrying current entries and usage, forcing the agent to consolidate in the same turn instead of a background process quietly dropping facts. (/docs/user-guide/features/memory)
4. **Counter-triggered self-improvement in a forked agent.** A separate `AIAgent` replays the conversation every 10 user prompts (memory) and every 10 tool iterations (skills), reusing the parent's prompt prefix byte-for-byte on a same-model route, and deferring to idle on contended local hardware. (/docs/user-guide/features/memory)
5. **Declared provenance as autonomy policy.** Only skills marked `created_by: agent` are eligible for autonomous curation; provenance is declared via `hermes curator adopt`, never inferred from telemetry, and every mutation is recorded in an append-only ledger with content-addressed blobs so a single change can be undone. (/docs/user-guide/features/curator)
6. **Evidence before judgment.** `/goal` quality gates are shell commands that must exit 0 before the LLM judge is consulted, and a red gate's exit code plus output tail becomes the next continuation prompt. `verify_on_stop` refuses a final answer on a turn that edited code without fresh test/build/lint evidence. (/docs/user-guide/features/goals, /docs/user-guide/configuration)
7. **Credential brokering at the network edge.** The sandbox holds only opaque tokens under normal provider env names while a host-side TLS-intercepting proxy swaps in the real key, behind a default-deny host allowlist and connect-time SSRF CIDR checks; sandbox creation refuses to start if the proxy would be bypassed. (/docs/user-guide/egress/iron-proxy)
8. **A safety floor that sits below every bypass.** A code-shipped hardline blocklist plus a user-editable `approvals.deny` glob list are evaluated before `--yolo`, `mode: off` and "always approve", with an explicit statement that this is a guardrail, not a sandbox — backend choice is the containment decision. (/docs/user-guide/security)
9. **Capability negotiation instead of hardcoded platform logic.** The Relay connector advertises `supported_ops` and per-platform flags at handshake; the gateway emits only advertised ops and degrades to text, so new platforms need no gateway change. (/docs/user-guide/messaging/relay)
10. **Progressive disclosure at both layers.** Skills load in three levels (index, body, linked file) and MCP/plugin tool schemas collapse into `tool_search`/`tool_describe`/`tool_call` bridges, so catalog size costs almost no context until something is actually needed. (/docs/user-guide/features/skills, /docs/user-guide/features/tool-search)
