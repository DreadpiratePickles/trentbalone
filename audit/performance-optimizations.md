## Approval gates

Do not auto-apply these classes of changes without explicit human approval:

| class | reason |
|---|---|
| RLS route refactors and RLS migrations | Tenant isolation is a P0 invariant and DB policy mistakes can leak or hide tenant data. |
| Money movement, ledger, invoice, Stripe, ERC-20, SPL, and payout changes | Requires transactionality, idempotency, and reconciliation review. |
| Provider provisioning changes | Can create, mutate, or delete external infrastructure and secrets. |
| Phase 5 worktree merge | Introduces schema, billing, marketing provider, and webhook surfaces into active root. |
| Budget reservation and spend accounting | Changes cost enforcement semantics and can block user-visible work. |
