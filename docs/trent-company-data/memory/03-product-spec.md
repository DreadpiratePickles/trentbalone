# Trent — Product Specification

**Upload this to Memory so the Engineer agent understands what we're building.**

---

## Product surfaces

### 1. Console (Dashboard)

Real-time view of what every agent is doing. Shows:
- Current cycle status and active job
- Open approvals badge with urgency
- Recent activity feed (agent actions, costs, completions)
- "Run cycle now" button for manual trigger

### 2. Command

The founder's primary input. A minimal chat interface that routes requests to the
right agent. Three modes:
- **Ask** — conversational Q&A, pulls from memory and vault
- **Agent** — hands off a scoped task to a specific agent role
- **Autonomous** — trigger a full company cycle from a single instruction

Model picker lets founders choose their preferred LLM per conversation.

### 3. Workbench / Trenchpad

The engineering surface. Agents autonomously plan, write, test, and deploy code.
- Session rail: list of active build sessions
- Work stream: live plan steps, file writes, terminal output
- Sandbox preview: live URL of running app
- Inline approvals: founder approves before agent merges to main
- Secrets panel: inject env vars safely without exposing them to the LLM

### 4. Vault (Wiki)

Obsidian-style knowledge base. Agents write here; founders read and edit.
- Folder tree with linked notes (wikilinks)
- Backlinks graph
- Full-text search
- Ask-with-citations: query the vault like a RAG system
- Auto-updated by agents (content, engineer, analyst)

### 5. Memory

Structured context uploaded by the founder. Agents read this at cycle start.
- Upload `.md`, `.txt`, `.pdf` files
- Chunked and embedded on upload
- Auto-surfaced when an agent's task is relevant

### 6. Reports

Structured outputs generated by agents on a schedule:
- Morning briefing (daily, 7 AM)
- Weekly operating report
- Investor update (monthly)
- Competitive landscape (on demand)

### 7. Artifacts

Files created by agents: PDFs, spreadsheets, dashboards, exported data.
Status flows: draft → needs_approval → approved → sent

### 8. Cycles

The operating heartbeat. Each cycle:
1. Sweeps all open tasks and drafts
2. Runs each agent in parallel
3. Collects outputs and approval requests
4. Posts morning briefing
5. Advances queue

### 9. Budgets

Spend guardrails:
- Monthly AI budget (hard cap on LLM spend)
- Weekly rollup cap
- Per-task cap
- Alerts at 80% utilization

### 10. Approvals

Human-in-the-loop gate. Agents pause and post here before:
- Publishing content
- Merging code
- Sending emails
- Charging money

### 11. Queue

Tasks waiting to run. Agents can add tasks; founders can prioritize or cancel.

### 12. Integrations

Connected tools that agents can use as actions:
- GitHub, Linear, Stripe, Resend, Slack, PostHog, Sentry, R2, Cloudflare DNS

### 13. Agent Plug (Marketplace)

Third-party agent discovery and install. Agents bought here slot into the same
cycle, budget, and approval system as built-in agents.

---

## Key invariants

- Agents never spend money without a budget check passing first
- Every agent action writes an audit log entry (immutable)
- All secrets are encrypted at rest; never passed raw to the LLM
- RLS isolation: one company's agents cannot touch another company's data
- Auth bypass is a dev-only flag; disabled in all deployed environments

---

## Current tech stack

- **Frontend:** Next.js 15, TypeScript, App Router
- **Backend:** Next.js API routes + Prisma ORM
- **Database:** SQLite (dev) / Neon Postgres (prod)
- **Auth:** NextAuth.js
- **AI:** Anthropic Claude (primary), OpenAI GPT (secondary), Gemini (tertiary)
- **Queue:** Upstash Redis / BullMQ
- **Storage:** Cloudflare R2
- **Deploy:** Vercel (frontend) + Railway/Render (workers)
