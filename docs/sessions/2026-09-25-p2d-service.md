## Decisions
- Label `uk.let-trent.<profile>` (the product domain is let-trent.uk), unit `trent-<profile>.service`.
  A profile name outside `[A-Za-z0-9._-]` is refused for install (it lands in a file name and a label).
- Components: gateway only if `gateway.enabled` (and a started gateway with no platform listening is
  a start failure: the user asked for it and nothing would answer); cron always; heartbeat only if
  `heartbeat.enabled`. A skipped component is logged as skipped, not a failure.
- One runtime for all three (surface "gateway" when the gateway is on, else "service"); one gateway
  manager shared by listeners, cron deliveries and heartbeat replies; the daemon adds a writer label
  "service" so `service status` finds the daemon's pid even with the gateway off.
- Stop order heartbeat, cron, gateway, then runtime cleanup, then the service writer. The heartbeat's
  `openHeartbeat().close()` is NOT used (it would stopAll the shared manager before the gateway's
  own stop); the daemon stops the loop and owns the manager lifecycle.
- launchd StandardOut/ErrorPath: `logs/service.stdout.log` / `logs/service.stderr.log`, never
  `service.log` itself, so the supervisor's lines are not written twice. `service.log` is capped
  at 1 MiB with one rotation to `service.log.1`.
- systemd: `SuccessExitStatus=130` because the daemon exits 130 after a signal-driven release; without
  it `systemctl --user stop` would leave the unit "failed".
