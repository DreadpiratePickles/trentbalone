## Findings while reading
- The hardline list protects `<profile>/.env` (`hardline.ts:36-37`, `write-to-trent-secrets`), and
  `ConfigManager.saveSecrets` is an atomic 0600 write that merges keys; `TrentSecretsSchema` is a
  `catchall(z.string())`, so token metadata (expiry, scopes) can live beside the tokens in one file
  and one write. That is the token store; nothing new on disk.
- `isSecretKey` routes by allowlist + `_KEY|_TOKEN|_SECRET|_PASSWORD` suffix; identifiers
  (`TWILIO_ACCOUNT_SID`, `GOOGLE_CLIENT_ID`) and metadata names would otherwise land in
  `config.yaml`, so every connect env name is registered in `EXTRA_SECRET_NAMES`.
- `live-platform-adapter.ts` `deps.tokenResolver` is `(input: {companyId, platform,
  externalAccountId}) => Promise<SocialCredential | undefined>`; `LiveSocialAdapterDeps` is not
  exported, so the CLI-side alias is derived with `Parameters<typeof createLiveSocialAdapter>[1]`.
- `workspace.ts` already uses a module-level test seam (`setWorkspaceConfirm`); the same pattern
  (`setConnectDeps`) keeps this task out of `context.ts`. `openBrowser` is exported by
  `web-server.ts` and reused.
- `registry.test.ts` probes every command with `--json --dry-run` and a `sample` argument, so
  `connect sample`, `connect remove sample`, `connect refresh sample` answer a dry-run payload
  with exit 0 instead of throwing.
- `docs-truth.test.ts` treats `trent connect stripe` in README as a subcommand claim; README uses
  `trent connect <provider>`.
