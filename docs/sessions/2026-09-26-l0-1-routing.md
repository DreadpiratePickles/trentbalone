- 01:55Z Design decisions (recorded before code):
  - G4 is enforced in two layers, both by PROVIDER: `planAttempts` (call-policy.ts) under any alias gives a
    pinned id to the alias's provider (never `inferProviderFromModel`); under a LOCAL alias it plans nothing
    on another provider (no pin fallback, no chain fallback). `applyModelEnv` under a local alias forces
    `MODEL_ALLOWED_PROVIDERS` to the alias's provider, so the app's own seat chain is the local endpoint only
    and the seat port never sees another provider's tier model. The seat port does not judge names under an alias.
  - Consequence for HOSTED aliases (deepseek/groq): a pin is the alias's (it was already documented as "a model
    id of the profile's provider"); the seat port no longer refuses by name, so the app's other-provider seat
    attempts reach the alias endpoint and fail there (no key leaks to a third party). Follow-up, not in scope:
    narrow the chain for hosted aliases too.
  - G1: `env-defaults.ts` writes only the model-NAME variables (the ones `MODELS` and `orchestrator-runtime.ts`
    freeze), never the alias identity, key or base URL (those are read per call and stay with `applyModelEnv`),
    so no non-run command sees `OPENAI_API_KEY=local`. Operator exports win (set-if-unset). A `run --model`
    pin in argv is forced (the P2-1 "before the libs load" contract, which G1 also broke).
  - The app-free part of `model-env.ts` moves to a new `orchestrator/model-env-early.ts` (tier tables, pin, the
    config.yaml reader); `model-env.ts` re-exports it. Reason: `model-env.ts` imports `fleet/seat-capabilities.ts`,
    which imports `@/lib/seat-manifest` and `@/lib/agent-catalog`.
