## Import chain (measured with a Bun `--preload` plugin recording every module load)

Clean worktree of 5d4c4a5, `bun apps/cli/src/index.ts run "say hi"` from a scratch cwd:
`apps/web/lib/store.ts` is first evaluated as load #495, immediately after `DATABASE_URL` became
set, followed by `orchestrator.ts, orchestrator-cache.ts, orchestrator-events.ts, queue.ts,
runtime-eval-overrides.ts, model-gateway.ts, tools.ts, orchestrator-run-persist.ts,
orchestrator-run-queue.ts` — exactly the `Promise.all` in
`packages/trent-core/src/orchestrator/libs.ts:183-193`. So the chain during a run is:

`apps/cli/src/runtime/headless.ts` (`createOrchestrator({ databaseUrl: "file:<profile>/trent.db" })`)
-> `orchestrator/index.ts:138` `applyStandaloneEnv(...)` sets `process.env.DATABASE_URL` to the
CORE store's SQLite URL -> `headless.ts` `orchestrator.ensureCompany()` -> `orchestrator/index.ts`
`loadLibs()` -> `orchestrator/libs.ts:183` `import("@/lib/store")` -> `apps/web/lib/store.ts:11`
selects `prismaStore` because the variable is set -> `prisma-store-base.ts` -> `apps/web/lib/db.ts:8`
`new PrismaClient()` (postgresql engine) -> `listCompanies()` -> `seedDatabase()` ->
`db.company.count()`.

The fleet-memory app tiers are NOT the first to reach the app store; the orchestrator itself is,
and it cannot skip it. Two consequences, both measured:

1. From source under Bun (durable store works), HEAD `trent run` exits 2 on the build machine:
   `Error validating datasource db: the URL must start with the protocol postgresql://` — the
   app's Postgres client was handed the wrapper's SQLite URL.
2. In the COMPILED binary the core store never opens at all: `createSqliteStore` reads
   `../../prisma/init.sql` relative to `import.meta.url`, which inside the compiled filesystem is
   `/prisma/init.sql` (probe binary: `ENOENT: no such file or directory, open '/prisma/init.sql'`),
   so `openStore` falls back to `EphemeralStore`, `durable` is false on every OS, `DATABASE_URL` is
   deleted and the app runs on `memStore`. `db.ts` still constructs the Prisma client when
   `loadLibs` imports `@/lib/store`; nothing ever queries it, so nothing handles the engine-load
   promise; on a machine without the engine it rejects unhandled and Bun kills the run. That is the
   stderr text in the report.

In the SHARED working tree (other agents' uncommitted `tools/social/{publish,matrix}.ts`)
`@/lib/social/live-platform-adapter` is imported STATICALLY, which imports `@/lib/store`, so the app
store is evaluated at CLI start-up before any env is set (load #518 with `DATABASE_URL` unset):
the run "works" on memStore but the Prisma client is constructed before any guard can run. This
re-opens the doctor's Linux death fixed in 5d4c4a5 for every command, once committed.

## Decision

Under invariant 1 the app's `DATABASE_URL` is the APP's database, never the wrapper's. One predicate,
`describeAppStore(env)` / `appStoreUsable(env)` in `fleet-memory/app-store.ts`, answers for
everyone: usable only for a `postgres://`, `postgresql://` or `prisma+postgres://` URL; unset, empty,
`file:` and any other scheme are "not used", each with one reason the doctor prints.

- `headless.ts` no longer hands the core store's `file:` URL to `createOrchestrator`; it hands the
  app's URL when usable, nothing otherwise (so `applyStandaloneEnv` clears an unusable value and the
  app stays on its in-process store), and installs `guardAppDatabase`: the app's own seam
  `globalThis.__prisma ?? new PrismaClient()` (`apps/web/lib/db.ts:8`) is filled with a guard object
  that throws a plain reason on any use, so the Postgres client — and its engine load — is never
  constructed in a process that has no Postgres.
- `loadAppMemoryModules` / `loadAppWriteModules` consult the predicate before any
  `import("@/lib/*")` and refuse with `AppStoreUnusedError`; the reader answers `[]` up front, the
  writers report "nothing written, no failure" (the doctor carries the reason), consolidate's
  `writeAppFacts` returns before loading.
- The doctor's `App Memory Tiers` says "not used" + reason without loading anything for every
  unusable state, and still measures a postgres URL with one read.
