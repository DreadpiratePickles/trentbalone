## Defect
`traces/OTelExporter.ts` was complete and tested but never instantiated outside tests, and it emitted
one flat `gen_ai.agent.turn` span per step with no parent ids and non-OTLP attribute encoding.

## What changed
- `config/telemetry-schema.ts` (new): `TelemetryConfigSchema { otlp_endpoint?: http(s) url, service_name: "trent" }`;
  `schema.ts` gains one import and `telemetry: TelemetryConfigSchema.default({})`; `defaults.ts` lists it.
  No schema version bump: passthrough config plus a defaulted key.
- `traces/OTelExporter.ts`: `parentSpanId` on spans, `recordSpan()`, `getEndpoint()`, deterministic
  `traceIdFor(runId)` (32 hex) / `spanIdFor(runId, key)` (16 hex), and `toOtlpSpan()` so `flush()` posts
  real OTLP/JSON (typed attribute values, nanosecond times as strings).
- `traces/bus-hook.ts` (new): `createOTelBusHook(exporter)` builds `trent.run` -> `gen_ai.agent.turn` ->
  `execute_tool <adapter>` from the bus (`run_start`/`run_*`, `step_start`/`step_end|step_blocked`,
  tool call records on `step_output`), dedupes re-emitted frames, exports on run end and on `flush()`,
  reports export failures through `onError` with the endpoint only. `composeBusHooks(...)` fans one
  orchestrator hook out to several.
- `doctor/checks/telemetry.ts` (new, check 14): unset -> `skip` with "not configured" in the line;
  set -> empty OTLP batch POST under the probe deadline -> ok / warn (404/405) / fail.
- `apps/cli/src/runtime/headless.ts`: `wireTelemetry(config)`; when an endpoint is set the OTel hook is
  composed with the improve hook and passed as the orchestrator's single `improve` bus hook;
  `HeadlessRuntime.telemetry` exposes it.
- `apps/cli/src/slash/index.ts` `/traces`: no fabricated trace rows, no glyphs, no hex; states the
  configured endpoint or "tracing off".
- Docs: `docs/configuration.md` telemetry block and span table; `docs/doctor.md` 13 -> 14 checks.
