- What the ranker already sees of a chunk (`brain-index.ts` `scorable`): `path title heading sheet
  text`. The page title and the heading breadcrumb are ALREADY prepended before TF-IDF and before
  embedding. So the "contextual prefix" of the cheap kind (title + section heading) is shipped; the
  deferred item is the LLM-written situating sentence (Anthropic's contextual retrieval).
- How the gate avoids live calls: offline the sweep binds the LEXICAL ranker only; `--live` adds
  the embedder. No recorded vectors exist anywhere; the hybrid has never been measured offline.
- The embedder (`embedder.ts`) embeds `[...candidates, query]` per call with a content-addressed
  disk cache, so a corpus is paid for once and each later query costs one query embedding.

## Code (all new, all under improve/; nothing in fleet-memory touched so far)
- `improve/docs-corpus.ts`: load + validate the fixture (zod, sha256 per file, unique ids), import
  it through `ingestDocuments`, resolve each phrase to chunk ids (must resolve, and only inside its
  own file), and `chunkScorableText` (the ranker's scorable string, restated; a test pins it).
- `improve/recorded-embedder.ts`: record/replay. The recording is each question's cosine against
  each chunk (float32), not the 3,072-d vectors (~10 MB); replay feeds `scoreAgainst` 2-d vectors
  `(1,0)` / `(c, sqrt(1-c^2))` so the shipped floor, blend, threshold and sort run unchanged. A
  miss is counted, because `scoreAgainst` swallows an embedder error and falls back to lexical.
- `improve/retrieval-metrics.ts`: recall@8 / recall@3 / MRR@8 per mode and category from the
  shipped `evaluateRetrieval` ranks; the embedding-only mode through the `rank` seam; no-answer
  abstention = the ranker returns nothing it calls related.
- `improve/docs-corpus.live.test.ts`: the live measurement, `TRENT_RECORD_DOCS_CORPUS=1` writes
  `fixtures/docs-corpus/embeddings.json`; asserts replay == live question for question.

## Failure analysis (scratch analyse.mts / sim.mts over the recorded cosines; no spend)
- Cosines are compressed on documents: a question against a 1,200-char chunk sits at 0.55-0.73
  (the 0.6 Gemini floor was calibrated on sentence pairs: unrelated 0.529, paraphrase 0.754). A
  zero-lexical chunk earns 0.6*(c-0.6)/0.4 and needs c >= 0.68 to reach recallMinScore 0.12.
- 7 of the hybrid's 21 misses were ranked 1-8 BY THE BLEND ITSELF and then dropped by the 0.12
  gate: para-05 (#2), para-07 (#8), para-10 (#1), para-12 (#1), hop-03 (#2), hop-04 (#4),
  hop-09 (#1). For para-10/para-12 the brain block was EMPTY although the answer was the best chunk.
- The other 14 are ordering failures: lexical noise (0.4 weight on incidental tokens) and dense
  ranks > 8.
- Ceiling: for a paraphrase (lexical 0 by construction) any fusion monotone in both signals ranks
  the answer no higher than its cosine rank. Dense order, no gate: paraphrased 8/12 = 0.667 < 0.8.
  So no reweighting/RRF/threshold change can meet the 0.8 bar; simulated for the record: RRF equal
  0.486, RRF 0.4/0.6 0.629 (0/5 abstain), dense no gate 0.686 (exact 0.833, 0/5 abstain).
- The cheap "contextual prefix" (page title + heading prepended before embedding) is ALREADY
  shipped: `brain-index.ts` scorable = `path title heading sheet text`, and the suite's spy test
  proves that exact string is what the embedder receives. It cannot be the fix; it is the baseline.
- Chosen fix (one hypothesis, stated from the analysis before simulating): brain recall admits a
  chunk when blend >= recallMinScore OR its cosine clears the embedder's own calibrated floor; the
  order stays the blend's. Predicted 0.400 -> 0.629 (22/35), exact 12/12, para 5/12, hop 5/11,
  abstain 3/5 -> 2/5. Zero per-query cost, no re-embedding. Run recall (`recall.ts`) untouched.
