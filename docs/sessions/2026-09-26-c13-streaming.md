## Open items (outside this agent's edit list; each is what switches a proven piece on in production)

1. `apps/cli/src/runtime/runner-for-mode.ts:226-229` `lazyGateway()` returns `{ complete }` only, so the real REPL,
   gateway and `trent run` never stream. It needs `stream: async function* (request) { yield* (await (gateway ??=
   createModelGateway())).stream(request); }` beside `complete`.
2. `apps/cli/src/commands/groups/servers.ts:180` and `service-daemon.ts:220` build the handler without `typing`.
   Each needs `typing: typingFromAdapters((platform) => manager?.getAdapter(platform))` (the lookup is read at send
   time, so building the handler before the manager is fine).
3. The REPL is line-granular: `repl/index.ts:195` `writeLine` appends the newline and `repl/engine.ts` (499 lines) has
   no partial write. Character-level streaming ("first text within 300 ms of the first delta" for a one-line answer)
   needs a partial-write seam there; the renderer side (`StreamedText`) would then return the raw delta.
4. The TUI runs the fleet only (`tui/App.tsx:155`); to show a solo stream, `App.tsx` keeps `streamedAnswer` state over
   the frames and passes it as `<Chat streaming>` (`tui/events.ts` needs no change: `step_delta` falls to `default`).
5. Observations, not changed: parse.ts shows a reply it cannot read as the envelope (fenced JSON, trailing text) raw as
   the answer, so `{"answer"` can reach the screen through the final answer frame, streamed or not; and text released
   before a headless `</think>` (thinking whose `<think>` was in the chat template) stays released. Both are in the
   parser's header as limits.
