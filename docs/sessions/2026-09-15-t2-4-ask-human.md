## Design as built

- Adapter `human` (`packages/trent-core/src/tools/human/index.ts`), tool `ask_human {question, context?, options?}`.
  Scopes `human`, `ask_human`: no side-effect token for the idempotency wrapper, no policy class for the
  rule evaluator, so a question never trips a trace rule and is never replayed from the idempotency store.
- Park/resume reuses the app's own tool-approval gate, unchanged: `requiresApproval` answers true, so the
  guardrail executor calls `dryRun`, which returns the `needs_approval` record with
  `details: {kind:"question", question, context, options}`; the seat loop pauses and the run parks on
  `step_awaiting_approval` / `run_awaiting_approval`. The core event mirror carries no new event kind:
  the question rides in the parked step's `seatLoopState.pendingToolCall.action` (and the
  `needs_approval` record's `details`), and `questionFromEvent(event)` reads it back on any surface.
- `Orchestrator.answer(runId, stepId, text)` stores the text in a `HumanAnswers` registry keyed by
  run/step and then calls the existing `approve`, which wakes the same parked-run waiter. The seat loop
  replays the pending call with `approvalGranted`; `execute` reads the answer through the tool-call
  context and returns it verbatim as the tool result. A release without an answer (a plain approve) is
  a `failed` record that says so; nothing is ever fabricated.
- Delegated child: the orchestrator marks the seat call delegated (`[delegated]` objective, the same
  rule fleet-memory uses) and the adapter returns `blocked` with a one-line reason instead of parking.
- Gateway: a question is an `ApprovalRow` with `kind: "question"`; no buttons; the card asks for a
  reply. `ApprovalBridge.answerQuestion` resolves the pending row delivered to that platform/chat when
  the sender is a paired admin there, storing the reply as `answer` and emitting `approval_decided`;
  `RunApprovalLink` routes it to `orchestrator.answer`. `GatewayManager.handleInbound` tries the
  question path before the agent handler sees the text.
- REPL: the question gate renders a question card and reads one line as the answer, on the same
  blocking path the approval card uses; `bindApprovalAnswers` routes `{answer}` to `orchestrator.answer`.
