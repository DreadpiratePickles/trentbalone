## Investigation (before any code)
- The embedder (`fleet-memory/embedder.ts`, 493 lines) posts `{model, input}` to Google's
  OpenAI-compatible `/v1beta/openai/embeddings`; no task type is sent, and that surface has no
  documented task-type field. The native `models/<m>:batchEmbedContents` takes `taskType` per
  request (`x-goog-api-key` header). So task types need a second, native client.
- `EmbedFn = (texts) => number[][]` and every ranker hands it `[...candidates, query]`, query last.
  A role per text has to travel with the call; the plan is an optional second argument
  (`{ roles }`), so a caller that passes none is byte-identical to today (run recall, search,
  failures, the doctor probe) and only the brain ranker opts in.
- The recorded-cosine replay (`improve/recorded-embedder.ts`) is keyed by text; a task-typed
  recording is a different table, so the recording must say which mode it holds and the replay
  must refuse a call made in the other mode (otherwise the suite measures the wrong space).
- Brain recall is called from `fleet-memory/orchestrator-hook.ts` (not owned) with `embed` only; the
  reranker reaches `recallFromBrain` as a new optional input. Metering: `orchestrator/run-hooks.ts`
  `recordRunModelCall(runId, call)` puts a call on the run's meter, whose rows carry the run's surface.
