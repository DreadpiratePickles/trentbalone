## Goal
Trent's A2A server answers Hermes v0.21.3's outbound client (A2A v1.0 on the wire) with a task it
can parse, while every 0.3.0 request keeps its exact current response. A translation layer at the
JSON-RPC edge, not a rewrite of `TaskLifecycle.ts`.

## Step 1 — what Hermes sends and reads (from source, before any code)
Read: `~/.hermes/hermes-agent/plugins/platforms/a2a/{tools.py,protocol.py,adapter.py}` (Hermes
Agent v0.21.3, upstream 49eb7b5d). Facts, each with its source line:

**Outbound request (`tools._send_task`):**
- One POST to `_rpc_url(base, card)` (`supportedInterfaces[].protocolBinding == "JSONRPC"` url
  first, then the card's top-level `url`, then the base). Headers from `_http_post_json`:
  `Content-Type: application/json`, `A2A-Version: 1.0` (`protocol.PROTOCOL_VERSION`), plus
  `Authorization: Bearer <token>` only when the peer entry has `auth: {type: bearer, token}`.
- Body: `{"jsonrpc":"2.0","id":"task-<16 hex>","method":"SendMessage","params":{"message":M}}`
  and `params.tenant` only when the card's interface or peer entry names a tenant.
- `M = protocol.text_message(ROLE_USER, text, context_id=ctx)`:
  `{"role":"ROLE_USER","parts":[{"text":<text>,"mediaType":"text/plain"}],"messageId":<32 hex>,"contextId":ctx}`.
  No `kind` anywhere; no `taskId` ever — Hermes continues an exchange by `contextId` only
  (`a2a_call(context_id=...)` reuses `ctx`; a fresh call gets `protocol.new_context_id()`).
- `a2a_call` is the ONLY outbound method. Hermes's client never sends `GetTask`,
  `SendStreamingMessage` or `CancelTask` (grep of `tools.py`: the single `"method"` literal is
  `"SendMessage"`). Streaming and GetTask exist only in its INBOUND adapter (`adapter.py`
  `_METHOD_TABLE`, which accepts both spellings: `SendMessage`/`message/send`,
  `SendStreamingMessage`/`message/stream`, `GetTask`/`tasks/get`, `CancelTask`/`tasks/cancel`,
  `ListTasks`/`tasks/list`, `SubscribeToTask`/`tasks/subscribe`, push-config CRUD; its
  `_find_task` reads `params.taskId or params.id`).

**What Hermes parses from the response (`_send_task`, `_reply_text_from_result`, `a2a_call`):**
- HTTP must be 2xx (urllib raises otherwise; 401/403/429 get their own messages).
- `resp["error"]` present → `ValueError("Peer '<agent>' returned an error: <message>")`.
- `resp["result"]` → `protocol.unwrap_send_message_response`: `result.task` if a dict, else
  `result.message` if a dict, else the bare result (so a 0.3 bare `Task` also parses).
- Reply text: first artifact with text (`protocol.extract_text(artifact)` reads every
  `parts[].text`; it tolerates `kind`), else `status.message`'s text, else the payload's own
  `parts`.
- `contextId` from the payload (else the ctx it sent); `state` from `payload.status.state`.
- `a2a_call` prints `state.replace("TASK_STATE_","").replace("_","-").lower()` (so 0.3 states
  also print) and appends the "needs more input — call again with context_id" hint ONLY when
  `state == "TASK_STATE_INPUT_REQUIRED"` (v1.0 spelling; a 0.3 `input-required` would not
  trigger it). This is the concrete reason to answer a v1.0 request with v1.0 states.

**Hermes's own v1.0 shapes (`protocol.py`), which the a2a-sdk parses strictly (its comment on
`build_task`: unknown fields are rejected by ProtoJSON parsers):**
- Task: `{id, contextId, status: {state: TASK_STATE_*, timestamp, message?}, artifacts?: [{artifactId, parts}]}` — no `kind`, no `createdAt`.
- States: `TASK_STATE_SUBMITTED|WORKING|INPUT_REQUIRED|COMPLETED|FAILED|CANCELED|REJECTED|AUTH_REQUIRED`.
- Roles: `ROLE_USER`, `ROLE_AGENT`. Parts discriminated by member presence: `{text, mediaType}`,
  `{url|raw, filename?, mediaType}`, `{data, mediaType}`.
- SendMessageResponse: `{"task": Task}` or `{"message": Message}` (oneof).
- StreamResponse frames: `{task}`, `{message}`, `{statusUpdate: {taskId, contextId, status}}`,
  `{artifactUpdate: {taskId, contextId, artifact}}` — no `kind`, no `final`; stream closure is
  the terminal signal. Each frame is a full JSON-RPC envelope in an SSE `data:` line.
- Card (`build_agent_card`): `supportedInterfaces: [{url, protocolBinding: "JSONRPC", protocolVersion: "1.0"}]`,
  `capabilities.extendedAgentCard`, and a top-level `url` kept "for pre-1.0 clients".
- Inbound version check (`adapter.py` l.238): an `A2A-Version` header other than `1.0`/`1.0.0`
  is refused with `-32602`; an absent header is accepted.

**Three-line summary:** Hermes sends `SendMessage` with a `ROLE_USER` message whose parts are
`{text, mediaType}` (no `kind`), under `A2A-Version: 1.0`, continuing by `contextId` and never
sending `taskId`. It reads `result.task` (or `.message`, or a bare task), takes the first text
artifact as the reply, and keys its "needs input" hint on the literal `TASK_STATE_INPUT_REQUIRED`.
It never calls `GetTask`, `CancelTask` or the streaming method outbound.

## Design, as built
- `packages/trent-core/src/a2a/v1.ts` (new, 214 lines): pure translation, imports only
  `spec.ts`. `a2aDialect(request)` is "1.0" iff the method is a v1.0 name. `toSpecRequest`
  maps `SendMessage`→`message/send`, `SendStreamingMessage`→`message/stream`,
  `GetTask`→`tasks/get`, `CancelTask`→`tasks/cancel`, `SubscribeToTask`→`tasks/resubscribe`,
  the four push-config names→`tasks/pushNotificationConfig/*`,
  `GetExtendedAgentCard`→`agent/getAuthenticatedExtendedCard`; `ListTasks` is refused `-32004`
  (no 0.3 equivalent). Inbound message: `ROLE_USER|ROLE_AGENT`→`user|agent`; a part `{text}`→
  `{kind:"text", text}`; `{url|raw}`→`{kind:"file"}` and `{data}`→`{kind:"data"}` so the
  lifecycle's own `-32005` check refuses them; `params.tenant` dropped. `GetTask`/`CancelTask`
  take `id` (v1.0) or `taskId` (Hermes's own tolerance). Outbound: `toV1Task` drops `kind`,
  maps states to `TASK_STATE_*` and roles to `ROLE_*`, parts to `{text, mediaType:"text/plain"}`;
  `toV1Result` wraps only `SendMessage` in `{task}`; `toV1StreamEvent` frames `{task}`,
  `{message}`, `{statusUpdate}` (no `final`), `{artifactUpdate}`.
- `rpc.ts`: `dispatchA2A` → if v1.0, refuse `ListTasks`, else `dispatchSpec(toSpecRequest(r))`
  and `toV1Result`; errors pass through unchanged (same codes in both specs). The 0.3 body moved
  verbatim into `dispatchSpec`.
- `A2AServer.ts`: `handleRpc` sets `A2A-Version: 1.0` on a v1.0-named request, translates the
  request, routes a `message/stream` (either name) to `handleStream(spec, res, dialect)`, whose
  frame writer maps through `toV1StreamEvent` for v1.0. CORS `Access-Control-Allow-Headers` now
  lists `A2A-Version` (a browser v1.0 client would otherwise fail preflight). No other 0.3 byte
  changes.
- `card.ts` / `spec.ts`: `supportedInterfaces: [{url, protocolBinding:"JSONRPC", protocolVersion:"1.0"}]`
  and `capabilities.extendedAgentCard: false`; `A2AAgentInterface` type added; 0.3 fields kept.
- `TaskLifecycle.ts` untouched.

## Card decision (step 4), with evidence
Advertise both. `supportedInterfaces` is the field Hermes's `_rpc_url` reads first and
`a2a_discover` labels from; before this change it was withheld because the root refused
`SendMessage` (`-32601`), and a card must not name a protocol its endpoint does not speak. The
root now answers the four v1.0 methods a client needs (`SendMessage`, `SendStreamingMessage`,
`GetTask`, `CancelTask`) in v1.0 shapes and refuses the rest with the codes v1.0 gives
(`-32003`, `-32004`), so the interface is true. The 0.3 fields (`protocolVersion: "0.3.0"`,
`url`, `preferredTransport`) stay because the 0.3 methods are answered at the same root and the
existing tests (`spec-transport.test.ts`) pin them. `capabilities.extendedAgentCard: false` is the
v1.0 spelling of the existing `supportsAuthenticatedExtendedCard: false`. Live result: Hermes's
`a2a_discover` prints `Protocol: JSONRPC v1.0` and `_select_jsonrpc_interface` returns the
interface, so the pre-1.0 warning is gone (verbatim below). Not advertised: `ListTasks`,
`SubscribeToTask`, push — there is no card field for them and each is refused with its code.
